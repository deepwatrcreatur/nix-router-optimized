The 4-Stage Declarative Pipeline

A deterministic engine replacing brittle imperative shell scripts and opaque web forms

Stage 01

Typed Topology

Interfaces, subnets, links, and VLANs are modeled as strict Nix types. Evaluation-time assertions catch IP overlaps and port conflicts at build time.

Stage 02

Derived Config

Firewall rule trees (nftables), DHCP pools (Kea), and DNS zones (Technitium) are deterministically compiled from your single source of truth topology.

Stage 03

Immutable Deploy

Generates bit-identical NixOS system closures. Deployed atomically via deploy-rs with instant rollback if networking drops.

Stage 04

Measurable Perf

Hardware-aware offloads (TSO/GSO/GRO), FastTrack connection bypass, CAKE bufferbloat shaping, and structured telemetry via routerctl.

Quick Start Examples

Copyable, battle-tested Nix configurations for your flake

# Single-Router Gateway with FastTrack & Unbound DNS
{ inputs, ... }: {
  imports = [
    inputs.router-optimized.nixosModules.router-networking
    inputs.router-optimized.nixosModules.router-dhcp
    inputs.router-optimized.nixosModules.router-dns-service
    inputs.router-optimized.nixosModules.router-firewall
    inputs.router-optimized.nixosModules.router-optimizations
  ];

  services.router-networking = {
    enable = true;
    wan.device = "eth0";
    routedInterfaces.lan = {
      device = "eth1";
      ipv4Address = "192.168.1.1/24";
      ipv6SendRA = true;
    };
  };

  services.router-dhcp.enable = true;
  services.router-firewall.enable = true;
  services.router-optimizations.enable = true;
}
# Dual-Node Keepalived (VRRP) with Golden MAC ISP Spoofing
{
  services.router-ha = {
    enable = true;
    role = "master";               # Set to "backup" on standby node
    virtualIp = "10.10.10.1/16";    # Floating Gateway IP
    vrrpInterface = "enp6s16";      # Internal LAN NIC
    preemptDelay = 300;             # Hold BACKUP 5 mins on recovery before taking VIP
    
    wan = {
      enable = true;
      interface = "enp6s17";
      clonedMac = "02:76:c6:01:2a:b0"; # Cloned ISP modem lease MAC
    };

    singleActiveUnits = [
      "kea-dhcp4-server.service"
      "inadyn.service"
    ];
  };
}
# Zero-Trust Zone Policy Configuration
{
  services.router-zones = {
    enable = true;
    zones = {
      wan.interfaces = [ "wan0" ];
      lan.interfaces = [ "lan0" ];
      iot.interfaces = [ "lan0.30" ];
    };

    policies = [
      { fromZone = "lan"; toZone = "wan"; action = "accept"; }
      { fromZone = "iot"; toZone = "wan"; action = "accept"; }
      { fromZone = "iot"; toZone = "lan"; action = "drop"; } # Isolate smart home devices
    ];
  };
}
# Composable PPPoE Uplink with Secret Protection
{
  services.router-networking = {
    enable = true;
    wan.device = "ppp0";
    wan.manageWithNetworkd = false;
  };

  services.router-pppoe = {
    enable = true;
    physicalDevice = "enp1s0";
    interfaceName = "ppp0";
    username = "isp-user@isp.net";
    credentialsFile = "/run/secrets/pppoe-peer.conf"; # Stored outside /nix/store
  };

  services.router-firewall.tcpMssClamp.enable = true;
}

Why Linux/NixOS Over FreeBSD/OPNsense?

Comparing the declarative fleet model with traditional web appliances

NixOS Router (`nix-router-optimized`)

  • Bit-Identical GitOps: Entire fleet defined in version-controlled Nix expressions.
  • Atomic Rollbacks: Broken deployments revert instantly via GRUB generations.
  • FastTrack Flowtables: Netfilter connection offload bypasses rule trees for 10G line rate.
  • eBPF / XDP: Drop malicious packets inside NIC ring buffers before kernel allocation.
  • State Sync: VRRP (Keepalived) + conntrackd replicates sessions without dropping calls.

FreeBSD Appliance (OPNsense / pfSense)

  • Turnkey GUI: Convenient PHP web UI for single-box administration.
  • Imperative State: Monolithic config.xml modified on disk at runtime.
  • Upgrades: In-place package updates; rollback requires full backup restore or ZFS snapshots.
  • No XDP Equivalent: Packet processing bound to classic kernel queue overhead.
  • State Sync: CARP + pfsync provides state synchronization, but confined to BSD pf.

Explore Framework Modules

Over 38 modular, composable building blocks for edge networking

router-networking

systemd-networkd engine for WAN DHCP/static, IPv6 Prefix Delegation (/56), and routed downstream interfaces.

router-ha

Dual-node VRRP high availability with Golden MAC cloning, preemption delays, and single-active unit orchestration.

router-firewall

Role-aware nftables policy engine with FastTrack flowtables, SIP-friendly bypass, hairpin NAT, and bogon filters.

router-zones

Declarative zone security matrix (WAN, LAN, IoT, DMZ) with high-level cross-zone traffic allowances and drops.

router-technitium

Technitium DNS integration with automated API token creation, TSIG AXFR secondary replication, and DoH/DoT.

router-kea

ISC Kea DHCPv4 server with RFC 2136/TSIG dynamic DNS registration, option 108 (IPv6-mostly), and HA hooks.

router-network-security

Passive AF_PACKET sensor wrapper for Suricata IDS with EveBox interface, plus Snort 3 and Zeek integrations.

router-tailscale

Subnet router and exit node automation with declarative route advertisements and firewall policy wiring.

router-wireguard

Kernel WireGuard tunnels for site-to-site mesh topologies and roadwarrior VPN access with declarative peers.

router-optimizations

Dynamic Python hardware offload negotiation (TSO/GSO/GRO), ring buffer expansion, and multi-queue IRQ affinity.

router-dashboard

Real-time web monitoring UI on port 8888 showing interface throughput, active connections, and tunnel status.

dns-blocklists

Declarative DNS ad-blocking presets (Hagezi, OISD, StevenBlack) with automated 24h cron updates.
